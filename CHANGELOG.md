# Changelog

## Unreleased

- F32/U8/U9/U12: `qur doctor`, `qur daemon ...`, `install.sh --skip-tests`. New module `queuer/selfcheck.py`. `qur doctor [--fix] [--json]` prints OK/WARN/FAIL with a fix hint for: daemon reachable; socket mode (0600) and owner (plus the private `/tmp/queuer-<uid>` fallback folder); config folder and `notify.json`/`redact.json` modes (files 0600, folder 0700, no symlinks, owned by you); database file, `-wal`/`-shm` and folder modes; log folder writable and free disk space (WARN under 1 GB, FAIL under 100 MB); systemd linger (`/var/lib/systemd/linger/<user>`, else `loginctl show-user`); unit file present and `systemctl --user is-active queuerd`; Telegram token (one `getMe` per bot, only if configured; offline is a WARN, a rejected token a FAIL; the token is never printed); database schema version (read-only open, nothing is created or migrated). Exit code 1 if any check FAILs. `--fix` repairs permission problems only (chmod of files/folders you own; never a symlink, a foreign owner, or a folder you moved with a `QUEUER_*` path variable); `--json` prints `{ok, summary, checks[]}`. `qur daemon start|stop|restart|status|logs` wrap `systemctl --user` / `journalctl --user -u queuerd` with fixed argument lists; `stop` and `restart` ask first when a job is running ("it will be recorded as interrupted") unless `--yes`/`-y`; `status` returns systemctl's exit code; `logs` takes `-n/--lines` (default 50) and `-f/--follow`. `install.sh install --skip-tests` skips the pytest run (nothing else changes; the default still runs the tests and stops on a failure); an unknown argument is rejected with the usage line. No DB migration, no new daemon command.
- F31/S4/S5: secret redaction for Telegram. New module `queuer/redact.py`. Everything sent to Telegram (finished-job message, Details, Logs tail, list and status text) is masked first, secrets become `***`. Built in: `NAME=VALUE` when the name ends in key/token/secret/password/passwd/passphrase or has a `secret`/`password` part (so `--tokenizer=gpt2`, `max_tokens=100`, `token_count=5` are left alone); `--password=VAL` / `--password VAL` style flags (same name rule); `Authorization: Bearer|Basic|Token ...` and a bare `Bearer <long token>`; AWS access key ids, GitHub tokens (`ghp_/gho_/ghu_/ghs_/ghr_/github_pat_`), Telegram bot tokens; the password in `scheme://user:pass@host`. Commands are masked word by word (so `--password="a b"` is hidden whole and display quoting stays right: `--token ***`), other text (Details cwd/log path/note/environment, the Logs tail) by pattern. User patterns: `~/.config/queuer/redact.json` (or `QUEUER_REDACT_PATH`; next to `notify.json` if that was moved), a JSON list of regexes, a match becomes `***` (only the first group if the regex has one); the file must be yours and not writable by others (a loose read mode is tightened to 0600; a symlink or foreign file is ignored); a bad regex, a non-string item or a pattern that matches the empty string is skipped with one journal line (never the pattern itself), at most 100 patterns, reloaded when the file changes. Local `qur show` / `qur logs` / `qur list` stay unredacted. README: new "Secret redaction" section, guidance to pass secrets via environment or files, not arguments. No DB migration.
- Phase 0 (housekeeping, DB foundations). Q7: new single-row `schema_version` table and numbered migrations (`db._MIGRATIONS`, steps 1-4 = the old column-probing migrations), each run in its own `BEGIN IMMEDIATE` transaction that also bumps the version, so a crash leaves the previous version intact and two processes cannot run a step twice. A fresh DB is created at the latest version; an existing DB without the table counts as version 0 and runs every step (the steps still probe the table, so a DB already at the latest shape just gets the version written, no data touched); a DB with a newer version than the code is refused with a clear error. Q8: every connection sets `journal_mode=WAL` and `busy_timeout=5000` (the daemon and `clean-logs` use the DB from two processes); the `-wal`/`-shm` files are chmod 0600 like the database. B9 regression test (a backgrounded child keeps its channel busy until it exits). Docs only: B9 "DECIDED: keep", F30/S2 "DECIDED: keep 0600", S6/F35 "DECIDED: accepted risk" (also in the README security section), F5/F33/F34 marked not planned, README notes "use several channels to run jobs in parallel" and the WAL/schema_version behaviour. DB migration: on first start an existing DB gets the new `schema_version` table (`CREATE TABLE IF NOT EXISTS`), set to 0 then walked to 4 by the no-op-or-fix steps, and switches to WAL (persistent; the `-wal`/`-shm` files appear next to it). No data is touched.
- F8/U4: `qur edit ID` edits a queued job. Flags: `--cmd` or words after `--`, `--cwd`, `--timeout` (0 = none), `--channel` (moves to the end of that channel), `--retries`, `--on-fail`, `--delay`/`--at`/`--clear-delay`, `--depends-on`/`--after-any`/`--clear-deps` (replace that kind / all), `--env`. Validated like `add` (executable, cwd, dependency and deadlock checks) and applied all or nothing; only `queued` jobs (not `--now` ones) can be edited. With no flags, command/cwd/timeout open in `$VISUAL`/`$EDITOR` (else nano/vi). EDIT LOCK: while an edit is open the job does not start and, strict FIFO, its channel waits; it runs the edited job once the edit is applied or abandoned. A lock whose holder process is dead, or older than 30 minutes (`db.EDIT_LOCK_SECS`), is cleared by the daemon; a daemon restart drops all locks; `rm`/`cancel` win over an open editor; a job already being spawned cannot be edited. `qur list` shows "editing" in Waits on, `qur show` an `editing` row. New daemon commands `edit_lock`, `edit_unlock`, `edit`. A new command or `--cwd` is resolved against the editing shell, whose PATH/VIRTUAL_ENV/PYTHONPATH replace the job's; `--retries 0` drops the retry delay. DB migration: new table `edit_locks (job_id, holder_pid, taken_at, expires_at)`, created on start with `CREATE TABLE IF NOT EXISTS` (no existing data touched).
- B14: retry delay. `qur add --retry-delay DURATION` (units s/m/h/d, chainable, at most 30d, needs `--retries`) makes an automatic retry wait before it may start: it gets `not_before = now + delay` (the F7 mechanism, so strict FIFO, restart-safe, exact wake-up). `--retry-backoff` (needs `--retry-delay`) doubles the wait per retry already made (delay, 2x, 4x, ..., capped at 30d). Default is unchanged (retry at once). A manual requeue is never delayed but copies the setting, like `--retries`; dependants of the failed job are still skipped at once. Shown as `retry delay` in `qur show` and the Telegram Details. The daemon's `add` takes `retry_delay_secs` (int) and `retry_backoff` (bool). DB migration: two columns on `jobs`, `retry_delay_secs INTEGER` (NULL = none) and `retry_backoff INTEGER NOT NULL DEFAULT 0`, added on start by `ALTER TABLE ... ADD COLUMN` (no data touched; existing rows get NULL/0).
- F4/U2: `qur wait ID|RANGE... | --channel N` blocks until the jobs end (or the channel is idle) and exits with a code that mirrors the outcome: 0 done, 1 failed, 2 cancelled/skipped/interrupted/removed, 3 daemon unreachable, 4 bad arguments or unknown job id (reported at once), 124 `--timeout`, 130 Ctrl-C; with several jobs the worst code wins (1, then 2, then 0). `--timeout DURATION`, `--quiet`, `--json` (final states). A job requeued by `--retries` is followed to its last attempt. It polls the existing `show`/`list` daemon commands every 1.5 s (no new daemon command). `qur show --json` and `qur status --json` already existed and now have tests. No DB migration.
- `install.sh`: the `full` hardening level (`ProtectKernelTunables/Modules`) is removed. It failed on some systems with `status=218/CAPABILITIES` ("Failed to drop capabilities") on every install before falling back, and added next to nothing for a user service. The levels are now `basic` (default) and `none`; `QUEUER_HARDEN=full` is rejected.
- F9/U3: history that scales. The daemon now keeps the last 200 finished jobs per channel instead of 10 (`QUEUER_KEEP=N` in the daemon's environment changes it; a bad value is ignored with a warning). A finished job a queued job depends on is still never pruned. `qur list` and the Telegram list still show only the last 10 (the Telegram list keeps its own caps: at most 100 finished jobs in the text, trimmed to 4096 characters, and 10 with buttons), and the "Recent" title now shows the real number and points to `qur history`. New `qur history` with `--status` (repeatable), `--channel`, `--since DURATION|DATE` (`2d`, `6h`, `2026-10-01`), `--grep TEXT` (raw command, case-insensitive), `--limit N` (default 50) and `--json`/`--full`; new daemon command `history`. `qur show` accepts ranges and comma lists (`31-33`) and keeps the order given. `qur clean-logs` is unchanged and works with the longer history. No DB migration.
- F1/B13: environment passthrough. `qur add --env KEY[=VAL]` (repeatable; `KEY` alone copies the value from the calling shell, names validated). A default passthrough list is copied from the calling shell when set there: `CUDA_VISIBLE_DEVICES`, `OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `LD_LIBRARY_PATH`, `LANG`, `LC_*`, `TERM`, `TZ` (the whole environment is never passed); override the list with `QUEUER_ENV_PASSTHROUGH` (comma-separated, `*` allowed, empty = none). Every job gets `PYTHONUNBUFFERED=1` unless `--env` says otherwise. Stored in `env_extra` (a sweep's `QUR_INDEX` wins over `--env`, `--env` over passthrough), kept by requeue and retry. `qur show` and the Telegram Details list it: passthrough names only, `NAME=value` for `--env`, `NAME=***` for names containing KEY/TOKEN/SECRET/PASSWORD. No DB migration. New module `queuer/jobenv.py`.
- B5: stopping the daemon no longer marks running jobs `failed`. New terminal status `interrupted` (note `daemon stopped`), used on a clean stop (SIGTERM/SIGINT: systemctl stop/restart, reboot; jobs are killed and the status is written before the daemon exits) and at startup for any row still `running`/`stopped` from a previous daemon (crash, SIGKILL, power loss). Not retried, does not count against `--retries`; the queue continues with the next job; Telegram says `interrupted (daemon stopped)` and Requeue works. `qur clean-logs` cleans interrupted logs too. `install.sh` waits for a stray daemon to finish stopping.
- F2: dependencies. `qur add --depends-on ID[,ID|A-B...]` (run only if all ended `done`, else the job is `skipped` with note `dependency N failed`, cascading) and `--after-any` (run once all ended, any outcome). Repeatable, combinable. Strict FIFO per channel: a waiting job blocks those behind it. Validated at add time (unknown id, dependency queued behind the job, cycles); `rm` of a depended-on queued job is refused, `cancel` skips dependants. `qur list` has a "Waits on" column, `qur show` and Telegram Details list the dependencies. Needs no migration beyond the `job_deps` table created on start (the `jobs` rebuild runs in one transaction).
- F3: sweeps. `qur add --each V1 V2 V3 -- CMD {}` (one job per value, `{}` replaced in every word that has it; error without `{}`) and `qur add --array A-B -- CMD` (one job per number, inclusive). Each job gets `QUR_INDEX` in its env (the number; for `--each` the 1-based position). Same channel/cwd/timeout/retries/dependencies for all, created in one transaction, at most 1000, and the created id range is printed ("added jobs 31-33"). The daemon's `add` takes an optional `jobs` list for this.
- F6: `qur add --on-fail pause|continue`. A `pause` job that ends `failed` (not cancelled/skipped/interrupted; for `--retries`, only the final failure) pauses its channel with the existing pause mechanism and sends "channel N paused after job X failed" to Telegram; resume with `qur resume`. `qur show` and the Telegram Details show it. Requeues and sweeps keep the setting.
- F7: delayed start. `qur add --delay 30m` (units s/m/h/d, chainable like `1h30m`) and `--at 22:00` (next occurrence in local time) or `--at "YYYY-MM-DD HH:MM"` (must be in the future). The time is stored as an absolute UTC `not_before` timestamp (column already created by the F2/F6 schema rebuild, so no further migration) and survives restarts. Strict FIFO: a delayed job at the head of its channel holds the channel until its time; the daemon sleeps exactly until `not_before` (capped at the 30 s recheck, so a clock jump or suspend cannot delay it by more than that). With dependencies both must be met; a failed dependency still skips it at once; a paused channel waits for `qur resume`. `qur list` has a "Starts at" column, `qur show` and Telegram Details/List show the start time. Applies to every job of a sweep. `--delay`/`--at` exclude each other and `--now`. Requeued and retried jobs are not delayed. Timeout counts run time only.
- Telegram: button presses that piled up while the daemon was off (more than 5 minutes) are dropped, not run late; a double tap on Requeue requeues once.
- `qur logs`: streams big logs instead of loading them; new `-n/--lines`.
- Idle workers wake on every real change and re-check only every 30 s (was every second).
- Socket: at most 32 connections at once.
- Telegram calls ignore proxy environment variables (token is in the URL); `QUEUER_USE_PROXY=1` opts back in.
- `install.sh`: uv is installed from a pinned release and SHA-256, not an unpinned installer script.
- CI: GitHub Actions runs the tests and a dependency audit.
- `--before/--after` help says clearly they set queue position only.
- `.gitignore` covers `.venv/` and `.pytest_cache/`; package description filled in.
